# settings/ on a Flipper SD card: what actually lives here
#
# NOTE FOR THIS WORKSPACE COPY:
# This file is a *documented placeholder* -- it contains no active settings.
# The Flipper firmware (development channel, which this machine runs) does
# NOT read a hand-written system_settings.txt. Verified against the current
# firmware source (applications/settings/system/system_settings.c):
#
#   - "Settings -> System" values (units, time format, date format, log
#     level/device/baud, hand orient, debug, heap trace, sleep method,
#     file naming) are stored in the MCU RTC registers via the
#     furi_hal_rtc_* API -- they are NOT persisted to an SD file at all.
#   - Per-app SD settings (desktop favorites, etc.) are written by the
#     device itself as binary saved-struct files (magic + version + struct,
#     e.g. desktop_settings.c), not as editable text.
#   - Some other apps keep their own text settings under their asset
#     folders (e.g. subghz/assets/setting_subghz.txt) -- again generated by
#     the app, not meant to be hand-authored.
#
# So: the right way to "have settings" on the device is to change them in
# the device UI. Do NOT sync hand-written settings files over the device's
# own files -- the device regenerates them on every change.
#
# Legacy reference (older firmware / community format, listed for
# documentation only -- current firmware ignores these):
#
#   system.rpc:false
#   system.vibro:true
#   system.notify:true
#   system.lcd_backlight:2
#   system.lcd_contrast:2
#   system.lcd_orientation:0
#   system.lcd_auto_backlight:false
#   system.lcd_auto_backlight_timeout:3
